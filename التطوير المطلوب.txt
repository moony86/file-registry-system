FSYS v0.8.5 – Windows User-Friendly Node App + Cleanup

الهدف:
تحويل FSYS Storage Node على Windows من تجربة مطور/CLI إلى تجربة مستخدم بسيطة قدر الإمكان، مع تنظيف التكرار والكود القديم غير المستخدم.

السياق:
v0.8.x الحالي يدعم:
- Windows portable package
- first-run setup wizard
- auto identity
- auto host
- MASTER_URLS fallback
- background registration
- LOCAL register
- Browse Local Library
- CACHED upload
- promote LOCAL→CACHED via operations queue
- status endpoint

المشكلة:
التجربة ما زالت تبدو مختبر:
- شاشة سوداء
- PowerShell
- .env يدوي
- bat files
- endpoints قديمة
- صعوبة على مستخدم عادي

المطلوب:
1. تنظيف آمن للكود القديم/المكرر.
2. تقليل الإعداد اليدوي.
3. إضافة واجهة Windows بسيطة للنود.
4. جعل التشغيل أقرب إلى “برنامج” وليس سكربت.

ممنوع:
- لا تضف HOT.
- لا تضف replication.
- لا تغير Master/Media/Stream.
- لا تكسر تشغيل Python الحالي.
- لا تحذف code بدون إثبات أنه غير مستخدم.
- لا تعيد كتابة Go.
- لا تستخدم حلول ضخمة مثل Electron.

المرحلة 1: Audit + Cleanup Plan
==================================================

قبل أي حذف:
افحص:

storage-node/app.py
storage-node/config.py
storage-node/routes/files.py
storage-node/routes/status.py
storage-node/services/*
scripts/*
docs/*
master-node/routes/files.py
master-node/static/js/dashboard.js
master-node/templates/dashboard.html

أعطني تقرير:
- endpoints مكررة أو قديمة
- functions غير مستخدمة
- ملفات قديمة أو debug فقط
- bat/scripts مكررة
- أي شيء متتبع في git وهو runtime
- مخاطر الحذف

لا تحذف مباشرة إلا الأشياء الواضحة جداً مثل:
- ملفات temp
- ملفات runtime tracked
- سكربتات build مكررة مثبت أنها غير مستخدمة

==================================================
المرحلة 2: Deprecate بدل Delete
==================================================

إذا وجدت endpoint قديم مثل:
POST /api/files/register

لا تحذفه فوراً إذا قد يكون مستخدم داخلياً.
اجعله:
- محمي token
- موثق deprecated
- يرجع header أو field:
  "deprecated": true
- أو أعد توجيه المنطق إلى register-local داخلياً إن كان آمناً.

القاعدة:
لا تكسر compatibility بدون سبب.

==================================================
المرحلة 3: Windows Node Control UI
==================================================

أضف واجهة بسيطة جداً للنود على Windows بدون Electron.

الخيار المفضل:
Tkinter لأنه مدمج مع Python غالباً.

ملف جديد:
storage-node/node_control.py

الواجهة تعرض:
- Node status
- Master connection
- active_master_url
- node_id
- node_host:node_port
- shared space used/free
- Local libraries
- أزرار:
  Start Node
  Stop Node
  Restart Node
  Open Dashboard
  Open Local Status
  Open Logs
  Setup / Reconfigure

مهم:
لا تجعل UI نفسها هي Flask server.
الواجهة تكون launcher/controller:
- تشغل fsys-node.exe أو python app.py كـ subprocess
- تراقب health عبر /api/status
- تعرض logs مختصرة

إذا التحكم بـ Stop صعب:
ابدأ بـ Start + Open Dashboard + Open Status + Open Logs + Setup.
Stop/Restart optional.

==================================================
المرحلة 4: Setup UX
==================================================

بدلاً من Wizard نصي فقط:
أضف خيار setup من الواجهة:
- Master URLS
- Token
- Shared Space Folder
- Storage Limit
- Local Libraries

إذا GUI setup ثقيل الآن:
أبقِ CLI wizard لكن أضف زر:
Setup / Reconfigure
يفتح:
fsys-node.exe --setup
في نافذة منفصلة.

المهم:
المستخدم لا يحتاج يفتح PowerShell بنفسه.

==================================================
المرحلة 5: Auto defaults
==================================================

حسّن Zero-config قدر الإمكان:

إذا .env غير موجود:
- أنشئ .env تلقائياً من defaults.
- NODE_ID=auto
- NODE_HOST=auto
- DATA_DIR=./data
- SHARED_SPACE_DIR=./shared_space
- THUMBNAILS_DIR=./thumbnails
- LOCAL_LIBRARY_DIRS الافتراضي:
  Windows Videos folder إن أمكن:
  C:/Users/<user>/Videos
  C:/Users/<user>/Downloads
  إن وجدت.
- MASTER_URLS:
  حاول اكتشاف master من:
  1. قيمة محفوظة
  2. localhost
  3. IP gateway subnet scan اختياري وخفيف فقط إذا آمن
لا تعمل scan ثقيل.

إذا لا يوجد Master:
- النود يشتغل
- الواجهة تقول:
  Waiting for master...
- وتسمح للمستخدم بإدخال Master URL.

==================================================
المرحلة 7: Logging
==================================================

تأكد:
- logs/node.log موجود
- UI يقدر يفتح ملف اللوق
- الأخطاء المهمة تظهر للمستخدم بلغة بسيطة:
  Master unreachable
  Firewall may block port 5001
  Shared space full
  Local library path invalid

لا تعرض stacktrace للمستخدم العادي إلا في logs.

==================================================
المرحلة 8: Firewall Guidance
==================================================

لا تحاول تعديل Windows Firewall تلقائياً الآن.

لكن:
- إذا /api/status يعمل محلياً والنود مسجل لكن لا يمكن الوصول من جهاز آخر، اعرض نص:
  Open TCP port 5001 in Windows Firewall.
- أضف docs مختصرة.

==================================================
المرحلة 9: Acceptance Tests
==================================================

A) Clean audit:
- أعطني ما أزلته وما أبقيته ولماذا.

B) Python run:
- تشغيل python storage-node/app.py ما زال يعمل.

C) Control UI:
- تشغيل node_control.py يفتح نافذة.
- زر Start يشغل النود.
- Open Status يفتح http://127.0.0.1:5001/api/status.
- Open Dashboard يفتح active master أو configured master.

D) First run:
- احذف .env.
- شغل UI.
- لا ينهار.
- ينشئ config أو يطلب setup بشكل مفهوم.

E) Package:
- build script يخرج dist/FSYSNode.
- المستخدم يشغل FSYS Node.exe.
- لا يحتاج PowerShell.

F) Existing features:
- Upload CACHED يعمل.
- Browse/Add LOCAL يعمل.
- Promote LOCAL→CACHED يعمل.
- Play يعمل.
