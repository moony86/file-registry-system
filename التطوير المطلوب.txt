FSYS v0.8.3 – Windows Portable Node Package

الهدف:
تجهيز Storage Node كحزمة Portable على Windows، تعمل بدون VS Code وبدون خطوات كثيرة.

السياق:
v0.8.2 يدعم:
- LOCAL register
- Browse Local Library
- CACHED upload
- Promote LOCAL→CACHED via operation queue
- runtime hardening
- master fallback
- auto identity

ممنوع:
- لا تضف Windows Service الآن.
- لا تضف HOT.
- لا تضف replication.
- لا تعيد كتابة Go.
- لا تغير Upload/Stream/Media.
- لا تكسر تشغيل Python الحالي.

==================================================
1) Build Script
==================================================

أضف سكربت:

scripts/build_windows_node.ps1

يقوم بـ:
- تنظيف dist القديم الخاص بالنود فقط.
- تشغيل PyInstaller بـ onedir.
- إخراج الحزمة في:
  dist/FSYSNode/

المطلوب داخل الحزمة:
- fsys-node.exe
- start_node.bat
- check_status.bat
- .env.example
- README_NODE_WINDOWS.md
- مجلدات فارغة:
  data/
  shared_space/
  thumbnails/
  logs/

لا تضع ملفات runtime حقيقية داخل Git.

==================================================
2) PyInstaller
==================================================

استخدم onedir وليس onefile.

السبب:
- أسهل في debug.
- أسهل مع ملفات config.
- أفضل كبداية.

تأكد من hidden imports إذا احتجت:
- flask
- flask_cors
- requests
- dotenv
- pg8000 إن كان مطلوباً للنود فقط لا تضفه إذا ليس مطلوباً
- services.*
- routes.*

لا تضف master-node داخل package.

==================================================
3) Portable config
==================================================

داخل package:

.env.example

يحتوي:

NODE_ID=auto
NODE_HOST=auto
NODE_PORT=5001

MASTER_URLS=http://192.168.1.14:5000,http://localhost:5000
FSYS_NODE_TOKEN=dev-token

SHARED_SPACE_ENABLED=true
SHARED_SPACE_DIR=./shared_space
SHARED_SPACE_LIMIT_BYTES=21474836480

THUMBNAILS_DIR=./thumbnails
DATA_DIR=./data

LOCAL_LIBRARY_DIRS=

FSYS_CORS_ORIGINS=http://192.168.1.14:5000,http://localhost:5000,http://127.0.0.1:5000

==================================================
4) First run behavior
==================================================

إذا .env غير موجود بجانب exe:
- انسخ .env.example إلى .env
- لا تسأل المستخدم الآن.
- اطبع رسالة واضحة:
  Created .env from .env.example. Please edit MASTER_URLS and LOCAL_LIBRARY_DIRS if needed.

هذا يجعل التشغيل الأول لا ينهار.

==================================================
5) start_node.bat
==================================================

ينفذ:

fsys-node.exe

ويترك النافذة مفتوحة حتى يقرأ المستخدم الأخطاء.

مثال:
@echo off
cd /d "%~dp0"
fsys-node.exe
pause

==================================================
6) check_status.bat
==================================================

ينفذ:

curl http://127.0.0.1:5001/api/status

أو PowerShell Invoke-WebRequest إذا curl غير متاح.

==================================================
7) Logging
==================================================

أضف logging أساسي إن لم يكن موجوداً:
- logs/node.log
- لا تكسر current console output.
- يكفي logging.basicConfig في app.py أو helper بسيط.

لا تبالغ.

==================================================
8) Path safety
==================================================

تأكد أن config paths النسبية:
./shared_space
./thumbnails
./data
./logs

تُحل بالنسبة لمجلد التشغيل الحالي بجانب exe.

مهم جداً:
عند تشغيل exe من dist/FSYSNode، لا تجعل shared_space يتولد داخل System32 أو مكان غريب.

10) Acceptance Tests
==================================================

بعد التنفيذ:

A) Build:
- شغل scripts/build_windows_node.ps1
- تأكد dist/FSYSNode موجود.

B) Files:
داخل dist/FSYSNode يجب وجود:

- .env.example
- start_node.bat
- check_status.bat
- README_NODE_WINDOWS.md

- شغل start_node.bat.

D) Status:

E) Master fallback:
- ضع MASTER_URLS برابط أول فاشل وثاني صحيح.
- شغل النود.
- active_master_url ينتقل للرابط الصحيح.

F) Upload:
- جرّب Upload صغير من dashboard.
- CACHED يعمل.

G) Local:
- ضع LOCAL_LIBRARY_DIRS في .env.
- جرّب Browse/Add Local.
- Play يعمل.
